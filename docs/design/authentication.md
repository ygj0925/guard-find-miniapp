# 蓝色认证体验设计规范

> 适用范围：`src/pages/auth/` 下的 uni-app 认证页面。视觉结构参考产品提供的移动端认证原型；原型中的绿色品牌交互已统一替换为蓝色，微信入口保留官方绿色。

## 1. 目标与边界

认证体验覆盖以下页面与前端状态：

- 账号密码登录：手机号、密码显隐、协议确认、忘记密码、验证码登录入口。
- 验证码登录/注册：手机号校验、图形验证码弹层、60 秒倒计时与协议确认。
- 微信小程序登录：填写手机号验证码后调用 `uni.login` 获取临时 code，再通过手机号验证码登录关联微信身份。
- 绑定手机号、重置密码、设置密码和用户协议。

手机号验证码关联微信已接入后端真实服务：行为验证码验证成功后请求 `GET /captcha/sms` 发送短信，随后以 `POST /auth/login` 的 `PHONE` 认证类型登录并关联微信。注册、密码重置等其余流程仍未接入真实服务。

## 3. 排版、间距与控件

- 页面默认使用 `rpx`，移动端以单栏为基线。
- 主标题：`44rpx`、700 字重；说明文字：`24rpx`。
- 输入与主按钮高度：`88rpx`；输入框、按钮圆角：`44rpx`（胶囊样式）。
- 弹层圆角：`24rpx`；桌面端认证卡片圆角：`36rpx`。
- 输入框必须保留可见错误文案和红色边框，不能仅通过颜色表达错误。
- 密码显隐、协议勾选、第三方入口均提供不小于 `88rpx` 的触达容器。

## 4. 响应式布局

| 视口 | 布局规则 |
| --- | --- |
| 小于 `768px` | 单栏认证页、居中标题与表单，匹配移动端原型的信息层级。 |
| 大于等于 `768px`（H5） | 左侧蓝色品牌展示区，右侧可滚动认证区域与白色表单卡片。 |
| 小程序 / App | 保持单栏；不依赖浏览器专属的桌面装饰能力。 |

安全区复用现有 UnoCSS `pt-safe`、`pb-safe`。认证页面使用自定义导航栏，以便提供原型中的返回与帮助区域。

## 6. 交互与表单状态

### 账号密码登录

- 手机号必须是 11 位中国大陆手机号；密码长度为 6-20 位。
- 用户未勾选协议时，账号登录和微信登录均显示明确错误并停止操作。
- 账号密码接口尚未接入，因此有效表单提交只显示“服务待接入”反馈。

### 验证码登录、绑定与重置密码

- 发送验证码前先校验手机号，再展示图形验证码弹层。
- 行为验证码校验成功后，请求 `GET /captcha/sms?phone=...&captchaType=blockPuzzle&captchaVerification=...`；短信接口成功后开始 60 秒倒计时。
- 微信入口获得的 `wx.login()` code 会连同手机号和短信验证码提交到 `POST /auth/login`，使用 `authType: "PHONE"` 与 `wxLoginCode`，由后端关联微信身份并返回 Token。
- 设置密码等尚未接入的流程不修改 Token、账户或密码。

### 微信小程序登录

`src/service/auth/wechat-auth.ts` 是唯一的微信登录适配层：

1. 仅在微信小程序端调用 `uni.login({ provider: 'weixin' })` 获取 code。
2. 前端仅导航到绑定手机号页；用户完成行为验证码与短信验证码并点击提交时，才调用 `uni.login` 获取 code，避免临时凭证过期。
3. 登录请求必须包含 `clientId`、`authType: "PHONE"`、`phone`、`captcha` 和新获取的 `wxLoginCode`；只在服务端返回 Token 后调用 `useTokenStore().completeExternalLogin()`。
4. H5/App 显示“请在微信小程序中使用微信登录”；取消授权或无 code 均显示可恢复错误。

## 7. 路由与安全

认证路由常量集中于 `src/router/config.ts`，包含登录、验证码登录/注册、绑定手机号、重置密码、设置密码和协议页。`src/utils/toLoginPage.ts` 使用同一 `LOGIN_PAGE`，避免 Token 失效时跳到已删除的 `/pages/login/index`。

`resolveAuthRedirect()` 仅接受以单个 `/` 开头的内部 uni-app 路由；缺失、损坏、外部 URL 或 `//` 协议相对 URL 都会回退至 `/pages/index/index`。

## 8. 无障碍与内容要求

- 输入框拥有明确 placeholder；错误文本紧邻对应输入框。
- 密码显示/隐藏和协议确认带有语义化标签。
- 禁用按钮不可触发提交；异步操作应显示“处理中”。
- 不用仅颜色传达成功、错误、选中或禁用状态；必须配合文本或勾选标记。
- 文案必须明确区分“开发演示”与真实服务，尤其是短信、注册、绑定、重置密码和微信登录。
